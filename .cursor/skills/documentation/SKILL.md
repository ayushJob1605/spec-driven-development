# Documentation Skill

## Purpose

Maintain concise, accurate project documentation and specification

artifacts.

## When to Use

Use this skill when:

- creating specifications

- modifying architecture

- changing API behavior

- changing the data model

- changing state transitions

- documenting architectural decisions

- updating project documentation

## Process

1. Identify the behavior or decision being documented.

2. Identify the appropriate specification artifact.

3. Check existing documentation before creating new content.

4. Update the existing artifact where possible.

5. Keep terminology consistent across artifacts.

6. Check for contradictions with other specifications.

7. Update traceability where appropriate.

## Rules

Do not duplicate information unnecessarily.

Do not document assumptions as facts.

Clearly distinguish:

- requirements

- decisions

- implementation details

- unresolved questions

Documentation should remain useful to both humans and AI agents.
