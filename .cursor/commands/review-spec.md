# Review Specification

Review the current project specification without implementing code.

## Review

Inspect the relevant files under `spec/`.

Check:

- completeness

- ambiguity

- contradictions

- missing acceptance criteria

- missing business rules

- missing edge cases

- API inconsistencies

- data-model problems

- state-machine problems

- security requirements

- non-functional requirements

- testability

- feasibility

- terminology consistency

## Output

Return:

### Findings

List confirmed issues.

### Questions

List information required from the human.

### Assumptions

List assumptions currently being made.

### Specification Changes

List required changes.

### AI Mistakes

Identify meaningful incorrect suggestions or assumptions made by AI

during specification development.

Do not invent findings.

### Status

Use one of:

- READY FOR PLAN

- NEEDS CHANGES

- BLOCKED

Do not implement application code.
